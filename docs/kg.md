## Ontology alignment (ADR 0003 D1, D2)

- SAREF v4.1.1 (`https://saref.etsi.org/core/`): State / StateOfInterest / StateValue pattern. `sa:On`, `sa:Off`, `sa:Standby` are minted because `saref:OnState`, `OnOffState`, `LightingDevice` and `OnCommand` were deleted in v4.1.1. Only two axioms are copied: `saref:Actuator ⊑ saref:Device`, `saref:Appliance ⊑ saref:Device`.
- BOT (`https://w3id.org/bot#`): Building → Storey → Space, `bot:containsElement`. `bot:hasElement` is never asserted.
- SOSA 2017: the room-selector observations and the ErrP observations only.
- `sa:` (`https://silentassist.example/ns#`) is our TBox; `:` (`https://silentassist.example/home#`) holds instances, so the README literal `:BedroomCeilingLight` appears as is.
- Risk tiers attach to **devices** (`sa:hasRiskTier`), not commands. Preset tiers are **computed**, not stored. `sa:ThermalHazardRule`: `sa:appliesToCommand sa:SetTemperature; sa:minSafe 18; sa:maxSafe 30; sa:tierIfViolated sa:HighRisk`.
- Rooms: Master Bedroom contains the Bedroom Ceiling Light, Bedside Lamp, Ceiling Fan, Air Conditioner and **Smart TV** (ADR 0003 D18 moves the TV from the KG brief's Living Room). Living Room contains the Living Room Light.

## Engine subset (ADR 0003 D4)

- Turtle: prefixes, IRIs, pnames, `a`, `;` and `,`, literals with escapes, lang and datatype, numeric and boolean shorthands, comments, blank nodes. Collections and non-ASCII names throw with line:col.
- SPARQL: `SELECT [DISTINCT]` / BGP / `OPTIONAL` / `FILTER` (with §17.2 error logic) / `ORDER BY` / `LIMIT` / `OFFSET`; parameterised queries through `opts.bindings`. UNION, MINUS, BIND, VALUES, GRAPH, subqueries, aggregates, property paths, CONSTRUCT, ASK and DESCRIBE throw `Unsupported SPARQL feature` (tested).
- Subclass typing is materialised at load (`SA.kg.store.create(triples, {subClassOf: true})`), so no property paths are needed.

## Resolver (ADR 0003 D6-D9)

`S(d) = gate(d) · clamp01(0.35·f_T + 0.30·f_S + 0.20·f_X + 0.15·f_R)`, rounded **once** to 4 dp, displayed with `toFixed(2)`.

| Feature | Value |
|---|---|
| gate | Hard: part of the SPARQL BGP `?d a <class> ; saref:hasFunction ?fn . ?fn saref:hasCommand <cmd>` |
| f_T | 1 for every gated candidate (typed with `sa:Light` / `sa:Fan` / `sa:AirConditioner` / `sa:Television`) |
| f_S | 1 if the active room `bot:containsElement` d |
| f_X | 1 if the command changes d's state (after clamping). f_X = 0 on the acted-on entity → `noop` → REJECT |
| f_R | n_d / K over the last K ≤ 10 `sa:Confirmed` executions of the same (command, class); K = 0 → 1/N |

- The resolver re-scores **all** gated candidates; the acted-on entity is the fixture the patient selected ("validate-focused"). `kgTop` is reported when it differs.
- The panel shows the **exact query string executed** (`resolved.query.text === SA.kg.resolver.lastQuery`; CQ5 is that text).
- **ErrP penalty (ADR 0002 D18):** ranking uses `S'(d) = S(d)·M(d)` from registered modifiers (`SA.errp.memory`). M never touches `s`. h-flag = M < 0.9 → EXECUTE becomes CONFIRM. With M at the 0.5 floor the ceiling goes 0.94 → 0.47 < Bedside 0.88, so the ranking flip and the second-best rule coincide.
- Command vocabulary (KG local names): `TurnOn`, `TurnOff`, `SetBrightness {value}`, `SetFanSpeed {value}`, `SetTemperature {value | delta}`, `SetMode {value}`, `ChannelUp`, `ChannelDown`, `VolumeUp`, `VolumeDown`; aliases `Power`/`TogglePower`, `Temp -`/`Temp +`, `TempDown`/`TempUp`. Presets: `{kind:'preset', id:'NightMode'}`.

### The honest account of 0.94 (ADR 0003 D10, verbatim)

| Candidate | f_R | S |
|---|---|---|
| Bedroom Ceiling Light | 6/10 | 0.35 + 0.30 + 0.20 + 0.15·0.6 = **0.94** (raw float 0.9399999999999998 → 0.94) |
| Bedside Lamp | 2/10 | **0.88** |
| Living Room Light | 2/10 | 0.35 + 0 + 0 + 0.03 = **0.38** (it is already ON, so f_X = 0) |

What is pinned and what is chosen:
- **Pinned by the README.** Since the ceiling light is perfect on type, space and state, the README's 0.94 fixes exactly one quantity: **w_R·(1 − f_R) = 0.06**.
- **Our free choice.** We chose (w_R = 0.15, seeded f_R = 6/10). The pair (0.20, 7/10) would hit 0.94 equally well. The history is a **synthetic 10-event seed** (6 ceiling / 2 lamp / 2 living) and is labelled "Synthetic seed history" in the UI and in TTL comments.
- **The split 0.35 / 0.30 / 0.20 is a documented design choice.** It follows the cue order type > space > state > habit. Any split with w_S + w_X > 0 preserves the ranking.
- **Why this is not hard-coded:**
  - S is recomputed live from SPARQL-fetched features on every decision.
  - Sensitivity table: f_R ∈ {0.4, 0.5, 0.6, 0.7, 0.8} → S ∈ {0.91, 0.925, 0.94, 0.955, 0.97}.
  - The selftest mutates the history and asserts that S changes.
  - The demo itself moves it. After "Retry → Bedside Lamp" is confirmed: ceiling 5/10 → 0.925, lamp 3/10 → 0.895.

| f_R | 0.4 | 0.5 | 0.6 | 0.7 | 0.8 |
|---|---|---|---|---|---|
| S (ceiling) | 0.91 | 0.925 | 0.94 | 0.955 | 0.97 |

## Semantic Context (ADR 0003 D11)

- **s = round2(S(acted-on entity) × P(active room))**, P(active room) = `sa:confidence` of the latest SOSA room observation = `SA.config.kg.roomConfidence` = 0.95. Canonical: 0.94 × 0.95 = 0.893 → **s = 0.89 → "89%"**.
- **Disclosure: 0.95 is README-pinned.** Given 0.94, the README's "89%" forces P(room) ∈ [0.9415, 0.9521]. The room selector is a simulated operator sensor, and it is labelled "simulated".
- Round2 because the policy consumes the displayed value, so every panel number is reproducible by hand (0.92 × 0.89 = 0.8188) and ADR 0002's canonical π = 1 − 0.819 = 0.181 is unchanged.
- Presets: s = gated steps / steps = 1.00, displayed `100% (explicit routine, KG-validated n/n steps)`. Single-candidate devices in the active room: s = 0.95.
- s is a heuristic score scaled by a simulated room confidence, not a calibrated probability.

## Policy (ADR 0003 D12-D14)

`c = round4(n × s)`; rules in order, first match wins:
1. noop → **REJECT** (`No change: <label> is already <state>`)
2. n < 0.40 or c < 0.50 → **REJECT** (`Not sure, please try again`)
3. tier High → **CAREGIVER APPROVAL**
4. Medium: c ≥ 0.85 → **EXECUTE**, else **CONFIRM**
5. Low: c ≥ 0.75 → **EXECUTE**, else **CONFIRM**
6. EXECUTE and h-flag (ErrP memory M < 0.9) → **CONFIRM**

Thresholds are declared constants (UX Chow derivation 0.77 / 0.88, rounded down to 0.75 / 0.85 and disclosed). The policy takes no ErrP credit (ADR 0002 D12). Trace example: `c = 0.92 × 0.89 = 0.8188 ≥ 0.75 (Low) → EXECUTE`.

## Risk tiers and the thermal rule (ADR 0003 D16, D17)

| Device / action | Tier |
|---|---|
| Lights, Ceiling Fan, Smart TV | Low: Autonomic |
| Air Conditioner (power, mode, setpoint in [18, 30] °C) | Medium: Guarded |
| Any setpoint < 18 or > 30 °C (strict; 18 and 30 are safe), whatever the AC power state, device action or preset step | High: Caregiver Approval |

- Advisory band [18, 20) or (26, 30] °C: `Advisory: outside the 20–26 °C comfort band for impaired thermoregulation`, no tier change.
- Preset tier = max over its non-no-op steps (computed): Night Mode Medium, All Lights Off Low, Cooling Mode Medium, Watch TV Low (asserted equal to `SA.config.policy.presetTiers`).
- `costClass`: light TurnOn/TurnOff → `light-select`; brightness, fan, TV channel/volume → `setting`; TV power → `power`; any AC command → `setting-medium`; preset → `preset`.
